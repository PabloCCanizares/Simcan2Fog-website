Parameters

NED parameter reference

How a value is resolved

Parameters have a type (int, double, string, bool), optional units (@unit(s), @unit(GB)), and a default. A value flows through four stages — the last one wins. Simcan2Fog leans heavily on parent forwarding, so a parameter can hold a value you never wrote in the INI.

Common mistakes

Missing required params

No zone → domain construction fails; numCpuCores=0 → VMs deadlock waiting for CPU.

Unit / type mismatch

An @unit(s) param needs "30s", not 30; an int can't take 10.5.

Domain collisions

Two nodes sharing a zone + name produce the same domain — later DNS registrations overwrite earlier ones.

Circular forwarding

Keep forwarding hierarchical (parent → child). A → B → A can't be resolved at init.
