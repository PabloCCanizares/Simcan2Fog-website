IoT Devices

Sensors, actuators and controllers for edge environments

Overview

To accelerate the composition of IoT scenarios, Simcan2Fog provides pre-configured modules that represent typical entities found in IoT environments. These include sensors for acquiring environmental measurements, actuators for performing physical actions, and controllers for coordinating edge operations.

All IoT device models are fully parameterizable, allowing researchers to customize their behavior, sampling rates, consumption patterns, and hardware specifications to match real-world devices or experimental requirements.

💡 Key Principle

IoT devices form the foundation layer of the fog computing hierarchy. They generate data at the edge, process simple operations locally via controllers, and can request fog or cloud resources for intensive computations.

Sensors

Sensors are one of the most important elements in IoT environments. Their role consists of acquiring measurements from the environment in which they are located. Simcan2Fog includes sensors from different categories, all of which can be included in the environments defined by the platform.

Sensor Configuration Parameters

Parameter Expected Value Unit Description
tag String - Label identifying the data type
distribution Distribution - Statistical distribution for sensor values
updatePeriod Integer seconds Interval between measurements
unit Unit - Unit of measurement for the data

⚙️ Customization

The behavior of all provided sensors can be modified by changing these configuration parameters. This allows you to model custom sensors or adjust existing ones to match specific experimental requirements or real-world device specifications.

Actuators

Another key element in IoT environments are actuators, whose objective is to perform actions in the environment. Simcan2Fog includes two types of actuators that can be incorporated into designed environments: automatic irrigation systems and smart bulbs.

Both actuator models have ON and OFF states that are reflected in the simulator's graphical interface. The base model records the time between each power-on and power-off event, which can be retrieved using OMNeT++ tools for statistical analysis.

Available Actuator Types

Actuator Configuration Parameters

Parameter Expected Value Description
consumption rate Integer Consumption of the unit per second
unit Unit Unit of the consumed resource

📊 Statistical Recording

The base model automatically records ON/OFF duration statistics. This information can be recovered through OMNeT++ statistical analysis tools to study usage patterns, energy consumption, and device lifecycle behavior.

Controllers

Since controllers are an element of particular relevance in IoT environments, Simcan2Fog provides models based on two latest-generation boards from renowned manufacturers: the Arduino UNO R4 WiFi and the Raspberry Pi 5.

These have been configured using specifications extracted from technical datasheets and performance benchmarks. Like other IoT components, any commercial computational element or prototype can be represented through parameterization.

Controller Responsibilities

The Controller module is responsible for:

  • • Receiving and preprocessing: Information from local sensors
  • • Running applications: Selected by the user to process IoT data
  • • Decision making: When to request service deployment to upper layers
  • • Coordinating responses: Actuator responses based on processing results

🔧 Custom Hardware

Just as these two specific examples have been configured, parameterization allows representation of any commercial computational element or prototype. You can model custom boards, industrial controllers, or experimental hardware by adjusting CPU cores, MIPS, memory, storage, and network interface parameters.

Configuration Example

Here's a complete example showing how to configure sensors, actuators, and controllers in a smart home scenario:

omnetpp.ini 
# Controller Configuration (Raspberry Pi 5)
*.controller.typename = "Raspberry5"
*.controller.numWlanInterfaces = 1
*.controller.energyStorage.typename = "IdealEpEnergyStorage"

# Sensor Configuration
*.sensor*.model.controllerInterface = "wlan0"
*.sensor*.model.controllerPath = "^.^.controller"

# Temperature Sensor
*.sensor1.model.tag = "temp"
*.sensor1.model.distribution = "uniform(20,25)"
*.sensor1.model.updatePeriod = 10s
*.sensor1.model.unit = "celsius"

# Luminosity Sensor
*.sensor2.model.tag = "luminosity"
*.sensor2.model.distribution = "uniform(400,100000)"
*.sensor2.model.updatePeriod = 10s
*.sensor2.model.unit = "lumen"

# Smart Bulb Actuator
*.lamp*.numApps = 1
*.lamp*.numWlanInterfaces = 1
*.lamp*.consumptionRate = 5 # watts
*.lamp*.unit = "W"

# User/Edge Configuration
*.user.deploymentZone = "local"
*.user.sensors = ["sensor1", "sensor2"]
*.user.localApps = [{"name": "LightController", "type": "LocalIotApplication"}]

Common Use Cases

1

Smart Home Automation

Temperature/humidity sensors trigger smart bulbs or HVAC systems via controller. Luminosity sensors adjust lighting based on natural light availability.

2

Smart Agriculture

Humidity sensors monitor soil moisture and trigger automatic irrigation systems. Temperature sensors optimize greenhouse climate control.

3

Health Monitoring

Wearable sensors collect heart rate, activity, and biometric data. Controllers preprocess and send alerts when abnormal patterns detected.

4

Smart Security

IP cameras generate video streams processed by controllers for motion detection. Results trigger alerts or activate lighting/alarm actuators.
