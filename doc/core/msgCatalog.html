Message Catalog

The typed .msg vocabulary

Two message families

Every interaction in Simcan2Fog is a typed message declared in an OMNeT++ .msg file (≈47 types). Internal traffic descends from SIMCAN_Message; network protocols (DNS, REST, IoT, blockchain) extend INET's FieldsChunk. An INET_AppMessage wrapper bridges the two so SIMCAN traffic can ride the real network stack.

Key operation & result codes

The operation field uses symbolic constants from SIMCAN_types.h (≈500–1005). Responses set isResponse=true and a result code.

VM & app

  • SM_VM_Req = 500
  • SM_VM_Sub = 502

Extending the catalogue

Custom protocols subclass an existing message — inheriting routing & tracing for free. Use the SM_ prefix and extend FieldsChunk instead when the type must interoperate with INET.

MyMessage.msg
import s2f.messages.SIMCAN_Message;

message SM_FederatedLearning extends SIMCAN_Message {
  int roundNumber;
  double modelWeights[];
  double accuracy;
  string aggregatorAddress;
}

💡 In Qtenv, right-click a message to inspect every field — including the trace[] path through the topology, the fastest way to diagnose routing bugs.
