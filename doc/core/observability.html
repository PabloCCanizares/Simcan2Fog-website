Observability

Signals, statistics & data collection

Signals, not print statements

Simcan2Fog exposes runtime state through OMNeT++ signals — typed events a module emit()s that recorders turn into result files. Producers and consumers are decoupled, so the same instrumentation feeds time-series, scalar summaries, and live inspection. You choose what to keep in the INI, trading detail for file size.

Recorder modes

record=OutputUse for
lastfinal scalarcapacity ceilings (maxCores) that never change
statscount · mean · stddev · min · maxcheap summary of a quantity over the run
vectortimestamped time-series (.vec)utilisation/latency curves — the costly one
countaccumulates emitted deltasturning +1/−1 emissions into a running total
histogrambinned distributionlatency / delay distributions
sum(field)derived sum over packet fieldstotal bytes via sum(packetBytes)

The delta trick: the ResourceManager emits +cores on allocate and −cores on release; a count recorder integrates these into a live allocatedCores curve — no shadow state needed.

Derived statistics for free

Emitting the packet object (not just a number) lets OMNeT++ filters compute metrics without any application bookkeeping:

End-to-end delay

dataAge(packetReceived) = now − packet creation time

Throughput

throughput(packetReceived) in bps

Bytes

sum(packetBytes) across all arrivals

IotApplication.ned
@statistic[endToEndDelay](
    source = "dataAge(packetReceived)";
    unit = s;
    record = histogram,vector;
    interpolationmode = none);   # discrete events

Three layers of metrics

① Correctness

Did it work? Accepted vs rejected VMs, successful vs failed resolutions, message counts in = out. Mostly scalars.

② Performance

How well? Utilisation (allocated/max), queueing delay, cache hit rate, latency percentiles. Vectors + histograms.

③ Downstream impact

Correlate the control plane with outcomes — e.g. stale DNS → connection failures, fog saturation → cloud offload latency. Join .sca/.vec by timestamp.

Recording without the bloat

omnetpp.ini
# default off, opt in to what you study
**.vector-recording = false
**.scalar-recording = true
**.resourceManager.allocatedCores.vector-recording = true

# window vectors to interesting intervals
**.allocatedCores.vector-recording-intervals = 0..1000, 10000..11000

⚠️ Over-instrumentation

Vectors for every signal across thousands of modules produce GB of .vec and crawl. Enable selectively.

⚠️ Eventlog cost

record-eventlog is great for sequence diagrams but the biggest slowdown — off for production runs.
