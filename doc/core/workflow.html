Experimental Workflow

Research-grade method, end to end

The experimental loop

A simulation earns scientific value through controlled comparison, not isolated observation. The discipline: change one factor at a time, repeat with independent seeds, and keep results traceable enough that a plot answers “which config, which params, which code, which seeds?” in 30 seconds.

Variables & metric hierarchy

Control your variables

  • • Independent: what you change (placement, queue size, delay)
  • • Controlled: held fixed (topology, load, seed policy, time limit)
  • • Dependent: what you measure (latency, throughput, drops, utilisation)
  • • Unit: one run = config + seed

Measure on purpose

  • • Primary: the decision metric (e.g. end-to-end latency)
  • • Secondary: explain why (queue occupancy, CPU util.)
  • • Sanity: is the run comparable? (completed reqs, drops)

Sweeps & deterministic seeds

Iteration variables make the run count a Cartesian product; tie the seed to the repetition so repeats are independent yet reproducible.

omnetpp.ini
[Sweep]
extends = Base
*.module.param   = ${p=10,20,40}     # factor 1 (3 values)
*.ctrl.strategy  = ${s="A","B"}     # factor 2 (2 values) → 6 combos

repeat   = 5
seed-set = ${repetition}          # seeds 0..4 → 30 runs total
output-dir = results/${configname}  # keep runs separated

⚠️ A fixed seed-set across all repeats reuses the same RNG stream — repetitions become identical and variance estimates are meaningless.

Traceable results

results/
2026-01-18-placement-study/
  README.txt   # the dossier
  ini/         # exact INI snapshot
  anf/         # scave recipes
  raw/         # .sca/.vec/.log
  export/      # CSV
  plots/       # figures

Traceability minimums

  • • Config path + section name
  • • Simcan2Fog commit / tag + INET/OMNeT++ versions
  • • repeat + seed-set policy
  • • The full swept-parameter list (copy from INI)
  • • .anf kept beside the CSV/plots

Pipeline: .sca/.vec → scave → CSV → Python/R

Bias checklist

Most “bad results” are workflow errors, not simulator bugs.

SymptomLikely causeFirst fix
Huge variance across runsToo few repeats; uncontrolled randomness↑ repeat; lock controls; document seeds
No meaningful differencesConfounded factor; wrong metric; saturatedCheck sanity metrics; verify the factor applied
Result explosion (GBs)Vectors/logging everywhereRecord only what you study; aggregate to scalars
Comparisons not fairDifferent load/topology/time limitOne extends base; change one factor
Not reproducibleImplicit code/INI/NEDPATH changesSnapshot INIs; pin versions & commits

Final ritual — before trusting any plot: the factor values were applied, the run count matches the sweep, the primary metric is computed identically across configs, and at least one sanity metric is comparable.
