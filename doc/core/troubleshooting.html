Troubleshooting

Symptom → cause → fix

Locate the layer first

Most failures look the same from the outside (“nothing happened”). Debugging is mostly about narrowing the layer: the telltale symptom usually points straight at it.

Common symptoms

Simulation aborts at startup

“Cannot cast module (null) to type X” — a path parameter (e.g. resourceManagerPath) points nowhere. Use an absolute path from the network root; confirm intermediate compound modules exist.

“support starting in node DOWN state” — node status is DOWN at init. Cross-module references must wait until the NEAR/MANAGER stage, not LOCAL.

A message never arrives

“Unknown received message” — a transport/INET packet leaked into a SIMCAN handler. Keep app messages on queueIn/Out and packets on socketIn/Out.

Wrong vector-gate index? Always store gateBaseId("…") at init and add the offset — never hardcode gate IDs.

Producer sends, consumer pulls, nothing is delivered

Almost always a topic / name mismatch — they're case-sensitive and whitespace-sensitive ("CloudProvider" ≠ "cloudProvider", "svc " ≠ "svc"). For DNS, a persistent NXDOMAIN means a zone-config typo or wrong ROOT→TLD→AUTH structure. Enable EventLog to read the exact strings.

VM rejected even though capacity looks available

Stale state — the CloudProvider's NodeDb lags the DataCentre (see the stale-state race). Or fragmentation — enough total cores, but no single blade fits the VM. Compare NodeDb (Qtenv WATCH) against the ResourceManager and log per-blade free resources.

Can't connect / connection refused

DNS may resolve fine but the IP isn't routable — wrong subnet or no route. Or a wrong smqIp. Verify the resolved IP belongs to the topology, the routing table has a path, and ports match (8444 push, 8443 pull, 53 DNS, 443 services).

Everything is slow / result files are huge

Over-instrumentation (vectors everywhere) or record-eventlog=true — the single biggest slowdown. Switch to Cmdenv, record only what you study, and use record=last/stats where you can.

The debugging toolbox

Message trace[]

Every SIMCAN_Message records each module + gate it crossed. Right-click it in Qtenv to see where it stopped.

EventLog

record-eventlog=true + eventlog-message-detail-pattern=*:operation,result,vmId → sequence diagrams of the real run.

Qtenv WATCH

Inspect NodeDb, ServiceTable and resource maps live, mid-run, to catch staleness.

EV logging

cmdenv-log-level=trace on a short run dumps every event; EV_DEBUG << msg->str() for targeted dumps.
