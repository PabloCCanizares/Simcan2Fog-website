Fog Nodes

Distributed compute layer for edge-to-cloud orchestration

What are Fog Nodes?

Fog nodes are compute-capable devices positioned in the intermediate layer between IoT edge devices and centralized cloud data centres. They form the core of the fog computing paradigm, bringing computational power, storage, and networking closer to data sources.

In Simcan2Fog, fog nodes are modelled as full-fledged compute nodes with routing capabilities, virtualization support, and local storage, enabling them to process workloads locally or forward them intelligently to other fog nodes or cloud data centres.

💡 Key Concept

Unlike traditional cloud computing where all processing happens in remote data centres, fog nodes enable distributed processing at the network edge. This significantly reduces latency, conserves bandwidth, and enables real-time applications that require immediate responses.

Core Capabilities

🔀

Intelligent Routing

Fog nodes act as network routers with full IP routing capabilities, forwarding traffic between IoT devices, other fog nodes, and cloud infrastructure.

  • • IPv4/IPv6 support: Full network stack via INET integration
  • • Dynamic routing: Support for routing protocols and network topology changes
  • • Multi-interface: Multiple network interfaces (Ethernet, Wi-Fi, cellular)
  • • QoS management: Traffic prioritization for latency-sensitive applications
📦

Virtualization & Containerization

Fog nodes can host virtual machines and containers, enabling flexible service deployment closer to the edge.

  • • VM hosting: Support for multiple VM types with configurable resources
  • • Container simulation: Lightweight containerized application deployment
  • • Resource isolation: CPU, memory, and storage allocation per service
  • • Live migration: Service migration between fog nodes for load balancing
💾

Local Storage

Each fog node includes local storage capabilities for caching, temporary data storage, and reducing dependency on cloud storage.

  • • Data caching: Store frequently accessed data locally
  • • Configurable capacity: Storage size and I/O throughput parameters
  • • Bandwidth reduction: Minimize data transfer to/from cloud
  • • Edge analytics: Process and store IoT data before cloud upload
⚡

Computational Resources

Fog nodes provide configurable computational capacity for processing edge workloads.

  • • CPU cores: Multiple cores with configurable MIPS ratings
  • • Memory: RAM capacity for running services and caching
  • • Scheduling: CPU schedulers for VM/container resource management
  • • Energy modelling: Power consumption simulation for energy-aware policies

Internal Architecture

🏗️

Fog Node Internal Structure

Components showing NetworkStack, Hypervisor, and resource management

A fog node in Simcan2Fog is composed of several internal modules:

Network Stack

Full INET network stack with IP routing, TCP/UDP protocols, and multiple physical interfaces. Includes QueueClient for Message Queue integration.

Hypervisor / Container Manager

Manages VM and container lifecycle (creation, startup, execution, migration, shutdown). Enforces resource allocation and isolation between services.

Storage Manager

Handles local storage operations, caching, and data persistence. Configurable with capacity and I/O throughput parameters.

Resource Monitor

Tracks current resource usage (CPU, memory, storage, network bandwidth) and reports to orchestration layer for placement decisions.

Request Processing Flow

When a fog node receives a service deployment request from the IoT layer, it follows this decision-making process:

1

Request Reception

Fog node receives a deployment request via Message Queue or direct network communication. Request includes resource requirements (CPU, memory, storage) and application characteristics.

2

Local Capacity Check

Node evaluates if it has sufficient available resources to handle the request locally. Checks current CPU usage, free memory, storage capacity, and network bandwidth.

3

Local Processing Decision

If resources available: Deploy service locally, create VM/container, and start application execution. This minimizes latency by processing at the edge.

If insufficient resources: Proceed to step 4.

4

Fog Mesh Forwarding

Node queries neighboring fog nodes in the mesh to find one with available capacity. Uses distributed coordination or centralized fog orchestrator to select target node. Forwards request to selected peer fog node.

5

Cloud Escalation

If the entire fog layer is saturated, the request is escalated to the Cloud Provider layer. Cloud provider assigns request to appropriate data centre using placement policies (first-fit, best-fit, zone-aware, etc.).

⚙️ Configurable Policies

The decision logic at each step is configurable. Researchers can implement custom placement strategies, cost-aware policies, energy-efficient algorithms, or latency-optimized routing to study different fog computing scenarios.

Configuration Example

Here's how to configure a fog node in your omnetpp.ini file:

omnetpp.ini 
# Fog Node Configuration
*.fogNode[*].typename = "FogNode"

# Compute Resources
*.fogNode[*].numCpuCores = 8
*.fogNode[*].cpuSpeed = 480000 # MIPS
*.fogNode[*].memory = "16GB"

# Storage Configuration
*.fogNode[*].storageCapacity = "1TB"
*.fogNode[*].storageIOSpeed = 500 # Mbps

# Network Interfaces
*.fogNode[*].numEthInterfaces = 2
*.fogNode[*].eth[*].bitrate = 10Gbps

# Virtualization Settings
*.fogNode[*].hypervisor.typename = "StandardHypervisor"
*.fogNode[*].maxVMs = 10

# Placement Policy
*.fogNode[*].placementPolicy = "BestFit" # Options: FirstFit, BestFit, WorstFit

# Energy Modelling (optional)
*.fogNode[*].energyStorage.typename = "SimpleEpEnergyStorage"
*.fogNode[*].energyConsumption.typename = "StateBasedEpEnergyConsumer"

Fog Mesh Topology

Fog nodes can be arranged in various topologies depending on the scenario:

🔗 Full Mesh

Every fog node is directly connected to every other fog node. Provides maximum redundancy and low latency between nodes, but requires more network links.

Use case: Small deployments, critical infrastructure

🌳 Hierarchical

Fog nodes organized in tiers (local, regional, backbone). Requests flow upward through hierarchy until resources are found or reach cloud layer.

Use case: Smart cities, wide-area deployments

⭐ Star

Central fog node acts as hub, with edge fog nodes connected to it. Simplifies routing and management, but creates single point of failure.

Use case: Campus networks, enterprise deployments

🔄 Ring

Fog nodes connected in circular topology. Provides redundancy with limited links, supports failover by routing in opposite direction.

Use case: Industrial control systems, resilient networks

Benefits of Fog Nodes

⚡ Reduced Latency

Processing data at the edge dramatically reduces round-trip time compared to sending all data to distant cloud data centres. Essential for real-time applications.

📉 Bandwidth Optimization

Local processing and caching reduces the volume of data transmitted over WAN links, lowering costs and alleviating network congestion.

🔒 Privacy & Security

Sensitive data can be processed locally without leaving the edge, improving privacy and compliance with data sovereignty regulations.

🌐 Offline Operation

Fog nodes can continue operating even when cloud connectivity is lost, ensuring service continuity for critical applications.

📊 Scalability

Adding more fog nodes scales capacity horizontally, distributing load across multiple locations instead of overloading centralized cloud.

💡 Context Awareness

Proximity to edge devices enables fog nodes to make location-aware and context-aware processing decisions for better service quality.
