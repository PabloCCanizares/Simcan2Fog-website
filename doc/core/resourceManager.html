ResourceManager

Allocation strategies & capacity tracking

The capacity oracle

The ResourceManager turns abstract VM requests into concrete blade allocations. It is the single authoritative view of available capacity inside a DataCentre or FogNode: blades register their capacity with it, a selection strategy picks where each VM lands, and signal emissions expose live utilization. It is a simple module with no gates — siblings call it directly through C++.

Caches capacity

Delegates bookkeeping to the NodePool.

Places VMs

FirstFit / BestFit (or custom) SelectionStrategy.

Reports usage

8 signals: capacity baseline + live allocation.

Where it sits

The node model

The NodePool holds a vector of Node structures — one per blade — each carrying its current free resources and a state bitmap.

Node.h
struct Node {
  enum State {
    ACTIVE     = 1, // powered on
    IN_USE     = 2, // has users
    MAXED_OUT  = 4, // no VM slots
  };
  NodeResources availableResources;
  int address;     // blade index
  uint8_t state;  // bitmap
};

NodeResources

  • • cores · memoryMiB · diskMiB — capacity
  • • vms · users — slot limits
  • • getLogicalDistance(vm) — sum of leftover resources after placing a VM, or DBL_MAX if it doesn't fit. This is the fitness metric BestFit minimises.

Selection strategies

The selectionStrategy parameter picks a class at init ("dc::FirstFit" by default, or "dc::BestFit"). Each implements one method: selectNode(vm, nodes, &index).

Atomic allocation with rollback

A request may carry several VMs that must launch together. allocateVms() places them one by one — and if any fails, it rolls back every reservation already made.

Signals & observability

Eight signals: four capacity baselines emitted once (record=last), and four allocation signals that emit + on reserve and − on release, so vectors track real-time utilization.

omnetpp.ini
# Allocation strategy (per node)
*.dc.resourceManager.selectionStrategy  = "dc::BestFit"
*.fg.resourceManager.selectionStrategy  = "dc::FirstFit"
*.*.pool.estimatedNumberOfNodes         = ${numBlades}  # pre-size the pool

# Record utilization vectors (skip disk to save space)
**.resourceManager.allocatedCores.vector-recording = true
**.resourceManager.allocatedRam.vector-recording   = true
**.resourceManager.allocatedDisk.vector-recording  = false

Common pitfalls

selectNode returns false

Either genuine exhaustion or fragmentation — enough total cores, but no single blade fits the VM. Log VM specs vs each node's free resources.

Negative final signals

A deallocation without a matching allocation — a lifecycle bug where termination arrives with no allocation record.

Wrong estimatedNumberOfNodes

Mismatched with numBlades causes vector reallocations during registration. The pool emits no warning — verify at finish time.

Custom strategy not found

Class 'X' not found means a missing Register_Class or a strategy source that never gets linked.
