IoT Showcase

Smart Home Simulation with IEEE 802.15.4

Overview

The IoT showcase implements a complete Smart Home simulation demonstrating the integration of IoT devices in a fog computing environment. The scenario models an automated lighting system based on luminosity sensors following the classic Sense-Process-Actuate pattern.

Key Concept: Edge IoT Control Loop

This showcase demonstrates a complete IoT control loop where sensors collect environmental data, a local edge controller (Raspberry Pi) processes the information, and actuators respond in real-time—all using standard IEEE 802.15.4 wireless communication.

🔍 Sense

4 luminosity sensors measure ambient light (400-100,000 lumen) every 10 seconds

⚙️ Process

Raspberry Pi controller runs LightController app with 100 MIs processing power

💡 Actuate

4 smart lamps receive UDP commands to adjust brightness

Wireless Communication Layer

IEEE 802.15.4 Physical Layer

The showcase uses industry-standard IEEE 802.15.4 wireless communication, commonly used in Zigbee, Thread, and other IoT protocols.

Radio Specifications

  • • Central Frequency: 2.45 GHz
  • • Bandwidth: 2.8 MHz
  • • Modulation: DSSS-OQPSK-16
  • • Bitrate: 250 kbps
  • • TX Power: 2.24 mW

Receiver Sensitivity

  • • Sensitivity: -100 dBm
  • • Energy Detection: -90 dBm
  • • SNIR Threshold: -8 dB
  • • Background Noise: -110 dBm

MAC Layer Parameters

IEEE 802.15.4 MAC Configuration

Header length: 72 bits

MTU: 118 bytes

CCA detection: 128 µs

Turnaround time: 192 µs

ACK wait: 560 µs

macMaxCSMABackoffs: 4

macMinBE: 3

macMaxBE: 5

macMaxFrameRetries: 3

Backoff method: exponential

Data Flow: Sense-Process-Actuate

1

SENSE - Data Collection

Luminosity sensors measure ambient light levels every 10 seconds:

  • • Measurement range: uniform(400, 100000) lumen
  • • Message length: 20 bytes
  • • Destination: controller:1000 (UDP)
  • • Transport: IEEE 802.15.4 wireless
2

PROCESS - Edge Computing

Raspberry5 controller executes LightController application:

  • • Listening port: 1000 (UDP)
  • • Processing power: 100 MIs
  • • Pings threshold: 5
  • • Decision logic: Evaluate luminosity data and determine lamp actions
3

ACTUATE - Control Action

Controller sends UDP commands to smart lamps:

  • • Target: lamp*:1000 (UDP)
  • • Actions: ON / OFF / DIM
  • • Transport: IEEE 802.15.4 wireless
  • • Lamp implementation: UdpSink receiver

Configuration Example

showcases/iot/omnetpp.ini 
# Network Configuration
network = SmartHome
sim-time-limit = 1h
simtime-resolution = ps

# Radio Medium Configuration
*.radioMedium.backgroundNoise.power = -110dBm

# Controller Configuration (Raspberry5)
*.controller.numWlanInterfaces = 1
*.controller.energyStorage.typename = "IdealEpEnergyStorage"
*.controller.wlan[0].typename = "Ieee802154NarrowbandInterface"

# Sensor Configuration
*.sensor*.model.controllerInterface = "wlan0"
*.sensor*.model.controllerPath = "^.^.controller"
*.sensor*.model.tag = "luminosity"
*.sensor*.model.value = uniform(400, 100000) # lumen
*.sensor*.model.unit = "lumen"
*.sensor*.model.updatePeriod = 10s
*.sensor*.model.messageLength = 20B
*.sensor*.model.destPort = 1000
*.sensor*.numWlanInterfaces = 1
*.sensor*.wlan[0].typename = "Ieee802154NarrowbandInterface"

# Actuator Configuration (Lamps)
*.lamp*.numApps = 1
*.lamp*.app[0].typename = "UdpSink"
*.lamp*.app[0].localPort = 1000
*.lamp*.numWlanInterfaces = 1
*.lamp*.wlan[0].typename = "Ieee802154NarrowbandInterface"

# Edge User Configuration
*.user.deploymentZone = "local"
*.user.sensors = ["sensor1", "sensor2", "sensor3", "sensor4"]
*.user.localApps = [{"name": "MyApp", "type": "LightController"}]
*.user.vms = []
*.user.remoteApps = []

# Network Settings
**.arp.typename = "GlobalArp"

What to Observe During Execution

Monitor these key behaviors to verify the showcase is working correctly:

  • • IEEE 802.15.4 wireless frames between sensors and controller at 2.45 GHz
  • • UDP packets to port 1000 containing luminosity data every 10 seconds
  • • LightController processing events with 100 MIs computation
  • • Control commands from controller to lamps based on threshold logic
  • • MAC layer ACKs and exponential backoff behavior during contention
  • • Energy consumption transitions across different radio states
📊

Expected Performance Metrics

Latency (Sensor → Lamp)

  • • Theoretical minimum: ~2 ms
  • • With MAC contention: 5-20 ms
  • • Frame transmission: ~832 µs per hop

Throughput

  • • Channel capacity: 250 kbps
  • • MAC efficiency: 60-70%
  • • Effective throughput: ~150-175 kbps

Design Rationale

This showcase demonstrates a realistic IoT deployment with several key design decisions:

Physical Layer Realism

Uses industry-standard IEEE 802.15.4 with accurate radio parameters, MAC behavior, and energy consumption modeling based on real hardware specifications.

Edge Computing Pattern

Demonstrates the Sense-Process-Actuate pattern with local edge processing on the Raspberry Pi controller, minimizing cloud dependencies.

Modular Architecture

Clean separation between sensors, controller logic, and actuators allows easy extension with additional device types and control algorithms.

Visual Feedback

Includes data link visualization and statistics tracking to help understand network behavior and debug communication patterns.

Extension Ideas
